## 结论先行

挂钩正确性通过：七个挂点的入口字节、参数位置（含栈上第 5/6 个参数）、两处返回地址判据、

## 优化（采纳）

- 七个挂钩点收敛成一张表 + 一条安装路径（同一件事实在表、`DetourFor`、安装循环、orig 全局量里写四遍，漏改不报错）。
- 删掉不可达的 orig 空指针守卫（守卫生效时不是报错而是给错答案，正是"静默降级"要避免的形态）。
- 删 `g_p1_orig` / `P1Fn`（只写不读，MinHook 允许 `ppOriginal` 传 NULL，已核 `hook.c:633`）。
- 100 ms 轮询 bool 改事件驱动 + 安静期落盘。
- `AllExpectedPresent` 与 `LogMissingPatterns` 合并；`Log` 单趟格式化；`presetStart` 死写；`SESSMASK_GET_RVA` 死宏；`kRawMaxOptions` 与 `kRawMaxRestore` 同义合并。

## 不采纳（记明理由，防下轮重复投入）

- 角色表线性查找：n 只有几十，改有序结构要引入新不变量。
- 两个 1024 项栈数组：缩小会把"截断不可能发生"变成可能。
- 函数指针合成结构体、`DirOfSelf` 换 `std::filesystem`、`/W4`：纯口味或要动构建参数，收益不抵风险。
- 日志每行 `fflush`、Worker 末尾死循环、`g_patches` 同时存 rva 与 hookRva：刻意如此。

## 执行结果（2026-10-26）

### 已改

**并发与生命周期**：`g_chars` 加 `std::mutex`；捕获与恢复都改成"锁内拷贝、锁外干活"；
恢复与改动漏斗之间加 `thread_local` 重入标记（xref 已确认 `0x16ABF60` 经 `0x16B6CF0`、
`0x16B8930` 回到 `0x16B74C0`）；落盘改为事件唤醒 + 300 ms 安静期；新增 `g_save_gen`，
写盘期间又有改动时不清脏标记而是再排一次。

**失败路径**：解析失败置"禁止写盘"，绝不用空库覆盖；跳过 UTF-8 BOM；写盘改
`CreateFile/WriteFile + FlushFileBuffers + MOVEFILE_WRITE_THROUGH`；失败保留脏标记并退避重试；
日志打不开时退到 `%TEMP%`。

**语义**：三槽全清空现在能存下来（以前会被旧值顶回来）；UI 管理器为空时记
(槽, 角色) 待恢复并在下一次构造或改动时重试；`autooffline_p3.txt` 限定 0..5。

**安装与结构**：七条 hook 合并进一张表、一条安装路径；原函数指针统一发布在
`MH_EnableHook` 之前；删掉 `InstallOneHook`、`InstallInteractionHook`、`InstallLoadoutHooks`、
`DetourFor` 里的重复分支、`g_p1_orig` 与不可达的空指针守卫。

**脚本**：EA 注册表 `tokens=3,*`（原先是死代码，已用临时注册表项复现）；`libraryfolders.vdf`
改成整行取回再剥引号（带空格的库路径原先被截成 `C:\Program`，已复现并验证新写法）；
自提权参数加引号（空格路径原先被拆成两个参数，已复现并验证）；三份脚本行尾统一 CRLF。
